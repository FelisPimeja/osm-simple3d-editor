# OSM Simple 3D Editor — план

Браузерный редактор 3D-атрибутов зданий OSM (схема Simple 3D Buildings).
Без бэкенда, хостинг на GitHub Pages.

## Архитектура

- **Карта:** MapLibre GL + векторные тайлы OpenFreeMap (подложка; здания тайлов — только ниже z15 и пока не загружены свои).
- **Здания:** на z ≥ 15 — свои данные по тайлам z14 (`src/view/overpass-tiles.ts`): память (LRU) → IndexedDB
  (`src/view/tile-store.ts`, своя база на источник) → сеть. Источник: Overpass (пул overpass-api.de / maps.mail.ru)
  с резервом OSM API `/map` (дробление на четверти при 400, отношения через `/full`); для тестового сервера — его API.
  Неполные ответы не кешируются; в индикаторе — источник и возраст тайлов, кнопка «Перезагрузить видимые тайлы».
- **Рендер:** three.js custom layer (`BuildingsLayer`), одна слитая геометрия на тайл, цвет и выделение в вершинах,
  крыши (в т.ч. straight skeleton в worker), плоские следы для контуров с частями и зданий нулевой высоты,
  оверлей поверх всего (`depthTest: false`) для подсветки выбираемого контура.
- **Правки:** единый режим — правки (`EditSession`) лежат поверх тайлов (оверлей подменяет объекты в тайлах),
  объекты начинают отслеживаться при первой правке. Можно создавать отношения `type=building` и менять их членов.
- **Запись:** OAuth 2.0 PKCE → свежие версии из API (`fetchElements`) → перенос правок (rebase тегов, слияние членов)
  → `changeset/create` → `upload` (osmChange `<create>`/`<modify>`) → `close`; записанное сразу попадает в кеш тайлов.
  Сервер по умолчанию — боевой (с подтверждением перед отправкой), dev — по выбору.

## Известные риски

- Тайлы отстают от OSM (дни) → локальный оверлей отредактированных зданий.
- `/map` ограничен 0.25 deg² и 50k узлов; отношения могут прийти неполными.
- Противоречия `height` vs `building:levels` — не перезаписывать молча, предупреждать.
- `colour` бывает hex или CSS-именем — сохранять в исходном формате.
- Правки геометрии (этапы 7–10) — минимальные: сложное (мультиполигоны, перенос узлов соседей, слияние)
  по-прежнему в iD/JOSM. Общие узлы с соседними зданиями двигать нельзя без явного подтверждения.
- Данные загружены только в пределах области редактирования: новые объекты и разрезы — только внутри неё.

- 2026-10-06, разбор тайлов OpenFreeMap (тайл 14/9904/5121, Кремль, сверка с Overpass):
  - id по Planetiler: `osmId*10 + 2` — way, `+3` — relation (подтверждено по площадям).
    Суффикс `0` (~45% фич) — Planetiler склеил несколько соседних зданий с одинаковыми атрибутами
    в один MultiPolygon; id взят от одного из них, тип потерян. Отсюда «ссылки ведут не туда».
    → В просмотре по клику ищем через API все здания внутри фичи. В режиме редактирования скрываем
    тайловые фичи по пересечению с bbox, а не по OSM id.
  - `colour` — сырое значение тега (`lightgrey;brown`, `azure`), не hex. Невалидное (с `;`) MapLibre
    рисует чёрным → берём часть до `;` и `to-color` с fallback.
  - `hide_3d` стоит только контурам из отношений `type=building` (14 из 658 фич). Обычные контуры
    с частями не помечены и рисуются поверх частей → эвристика `findOutlinesWithParts`
    (src/tiles/outlines.ts): скрываем фичу с min=0, если вложенные фичи с `min < её height` покрывают ≥50%.
    На тестовом тайле: из 29 контуров с частями 12 помечены hide_3d, эвристика добавляет ещё 10;
    ложных срабатываний 3 (перекрывающиеся части башен Кремля). Ограничивать высоту частей нельзя:
    контуры часто размечены ниже своих частей.
- 2026-10-06, контуры с частями в просмотре (вариант «вычитание»):
  - Вместо скрытия контур заменяется остатком A − ∪B (polygon-clipping), отдельный GeoJSON-слой
    `simple3d-outline-remainders` на высоте контура. Фичи, разрезанные границей тайлов, обрабатываются
    по всем кускам.
  - Полное вычитание — если вложенные фичи покрывают ≥50% площади; иначе вычитаются только

  - Предел подхода: в тайлах нет признака building/building:part. На Кремле ~половина частей
    содержит вложенные более низкие части, и по покрытию их от контура не отличить (даже при 70%

    свои тайлы (Planetiler-профиль + PMTiles) или рендер по API/Overpass на крупных зумах.
  - Стоимость пересчёта ~0.4–0.7 с на тайл z14 в плотной застройке — при необходимости вынести в worker.

  - Кеш тайлов: формат 4 (группы с ролями); записи формата 3 читаются с ролью `'?'` (совпадение членов только по type/ref).
  - Контур с частями (`markOutlinesWithParts`): учитываются части, низ которых ниже верха контура минус 1 м
    (`computeHeights`), положение части — `pointOnSurface` (центроид U-образной части выпадал из контура);
    покрытие ≥ 50% → контур рисуется плоским следом.
  - Объединение: кандидат в контуры — любой объект с тегом `building`; приоритет — выбранный вручную, затем
    единственный «чистый» `building` без `building:part`.
  - Крыши: почти коллинеарные вершины (< 12°, < 0.5 м) убираются перед скелетом — иначе «веер» на round.
  - Overpass временами отвечает 504/406, OSM API `/map` — 429 под нагрузкой; перезагрузка тайлов повторяется.
