# OSM Simple 3D Editor — план

Браузерный редактор 3D-атрибутов зданий OSM (схема Simple 3D Buildings).
Без бэкенда, хостинг на GitHub Pages.

## Архитектура

- **Просмотр:** MapLibre GL + векторные тайлы OpenFreeMap (схема OpenMapTiles).
  Слой `building`: `render_height`, `render_min_height`, `colour`, `hide_3d`.
  Крыш в тайлах нет — в просмотре они плоские.
- **Редактирование:** загрузка данных из OSM API 0.6 (`/map?bbox=`, `/way|relation/{id}/full`),
  собственный рендер в three.js через custom layer MapLibre (стены + крыши).
  Тайловые здания в области редактирования скрываются.
- **Запись:** OAuth 2.0 PKCE → `changeset/create` → `upload` (osmChange) → `close`.
  Сначала только на `master.apis.dev.openstreetmap.org`.

## Известные риски

- Тайлы отстают от OSM (дни) → локальный оверлей отредактированных зданий.
- `/map` ограничен 0.25 deg² и 50k узлов; отношения могут прийти неполными.
- Противоречия `height` vs `building:levels` — не перезаписывать молча, предупреждать.
- `colour` бывает hex или CSS-именем — сохранять в исходном формате.
- Правки геометрии вне MVP — отправлять в iD/JOSM.

## Заметки по ходу

- 2026-10-06, этап 1:
  - maplibre-gl 6.x + Vite: нужно `optimizeDeps.exclude: ['maplibre-gl']`, иначе не грузится worker.
  - В тайлах OpenFreeMap слой `building` отдаёт только `render_height`, `render_min_height`, `colour`
    (`hide_3d` в выборке не встретился, но части зданий с `render_min_height` > 0 есть).
  - (уточнено ниже) `feature.id` присутствует: `osmId = floor(id / 10)`. Проверено на Кремле:
    `33347753` → relation/3334775, `13593720` → relation/1359372 (Никольская башня),
    `2394726050` → way/239472605. Суффикс 3 встречался только у relation, суффикс 0 — и у way,
    и у relation, так что тип по id не определяется однозначно. Решение: пробовать way и relation
    через API (или сверять с загруженным bbox). Связь тайл → OSM есть, хоть и с этой оговоркой.
- 2026-10-06, этап 2:
  - Загрузка: `/map.json` по экрану (лимит 0.0004 deg²) + `/relation/{id}/full` для мультиполигонов
    с членами вне bbox (без этого на Кремле терялось 72 из ~1800 объектов).
  - Рендер: three.js custom layer, локальная система в метрах от центра bbox, матрица из
    `defaultProjectionData.mainMatrix`. Выбор — raycast через обратную матрицу.
  - Крыши: flat, pyramidal, dome, onion, skillion (любой одиночный полигон), gabled/hipped (только 4 вершины).
    Остальное (round, gambrel, mansard, gabled на сложных контурах) — стены до верха + плоская крыша с предупреждением.
    Статистика по Кремлю: skillion 269, gabled 136, pyramidal 104, hipped 102, round 61 — следующие кандидаты: round и gabled/hipped через straight skeleton.
  - Тайловые здания в области скрываются фильтром `floor(id/10) in [osmIds]`.
  - Кнопку редактирования включаем только после `load`, иначе добавленные слои теряются при загрузке стиля.
- 2026-10-06, разбор тайлов OpenFreeMap (тайл 14/9904/5121, Кремль, сверка с Overpass):
  - id по Planetiler: `osmId*10 + 2` — way, `+3` — relation (подтверждено по площадям).
    Суффикс `0` (~45% фич) — Planetiler склеил несколько соседних зданий с одинаковыми атрибутами
    в один MultiPolygon; id взят от одного из них, тип потерян. Отсюда «ссылки ведут не туда».
    → В просмотре по клику ищем через API все здания внутри фичи. В режиме редактирования скрываем
    тайловые фичи по пересечению с bbox, а не по OSM id.
  - `colour` — сырое значение тега (`lightgrey;brown`, `azure`), не hex. Невалидное (с `;`) MapLibre
    рисует чёрным → берём часть до `;` и `to-color` с fallback.
  - `hide_3d` стоит только контурам из отношений `type=building` (14 из 658 фич). Обычные контуры
    с частями не помечены и рисуются поверх частей → эвристика `findOutlinesWithParts`
    (src/tiles/outlines.ts): скрываем фичу с min=0, если вложенные фичи с `min < её height` покрывают ≥50%.
    На тестовом тайле: из 29 контуров с частями 12 помечены hide_3d, эвристика добавляет ещё 10;
    ложных срабатываний 3 (перекрывающиеся части башен Кремля). Ограничивать высоту частей нельзя:
    контуры часто размечены ниже своих частей.
- 2026-10-06, контуры с частями в просмотре (вариант «вычитание»):
  - Вместо скрытия контур заменяется остатком A − ∪B (polygon-clipping), отдельный GeoJSON-слой
    `simple3d-outline-remainders` на высоте контура. Фичи, разрезанные границей тайлов, обрабатываются
    по всем кускам.
  - Полное вычитание — если вложенные фичи покрывают ≥50% площади; иначе вычитаются только
    не более низкие (башня на основании).
  - Предел подхода: в тайлах нет признака building/building:part. На Кремле ~половина частей
    содержит вложенные более низкие части, и по покрытию их от контура не отличить (даже при 70%
    ~20 частей получат «ямы»). Полностью корректный просмотр требует данных с признаком части:
    свои тайлы (Planetiler-профиль + PMTiles) или рендер по API/Overpass на крупных зумах.
  - Стоимость пересчёта ~0.4–0.7 с на тайл z14 в плотной застройке — при необходимости вынести в worker.
- 2026-10-06, просмотр через Overpass (после тега `openfreemap-tiles`):
  - На z ≥ 15 здания тайлов z14 подменяются данными Overpass (`src/view/overpass-tiles.ts`):
    запрос по bbox тайла, ≤2 параллельно, ≤12 ближайших к центру тайлов, LRU-кеш на 48 тайлов,
    повтор с экспоненциальной паузой при 429/504. Рендер — тот же three.js-слой, группа на тайл.
  - Тайловые фичи подменённого тайла скрываются по id (через внутренний `style.tileManagers`),
    склеенные полигоны — по свойству `tile`. MapLibre при overzoom хранит тайлы с координатами
    текущего зума (17/x/y), поэтому ключи приводятся к родителю z14.
  - Overpass-api.de: 4 слота на IP; без браузерного User-Agent отвечает 406 (только для отладки из node).
    Тайл z14 с Кремлём — ~1600–2600 объектов.
- 2026-10-06, этап 3 (редактирование тегов):
  - `src/edit/session.ts` — исходные теги из API, текущие (Feature3D.tags меняется на месте), история undo/redo,
    список изменений с diff по тегам. `src/edit/tag-form.ts` — форма с валидацией (длины, целые,
    направление 0–360/румбы, CSS-цвета), пустое поле удаляет тег, нестандартные значения select сохраняются.
  - После правки пересобирается только меш изменённого объекта (`BuildingsLayer.updateFeature`).
  - Выход из режима и закрытие страницы с несохранёнными правками — с подтверждением.
- 2026-10-07, этап 4 (вход и отправка) — проверено на dev-сервере:
  - Сервер выбирается в панели (dev по умолчанию); данные для редактирования грузятся с него же — id и версии
    на dev и боевом не совпадают. Поиск по id тайлов в просмотре всегда идёт в боевой API.
  - OAuth 2.0 PKCE во всплывающем окне, возврат через `oauth.html` (postMessage), токен в localStorage по серверу.
    client_id — из `VITE_OSM_DEV_CLIENT_ID` / `VITE_OSM_CLIENT_ID` (`.env.local`, см. `.env.example`).
  - `src/osm/upload.ts`: changeset create → upload osmChange (`<modify>` с полной геометрией из API) → close
    (close и при ошибке). На 409 — перечитываем элементы и переносим правки на свежую версию, если чужие правки
    не трогали те же теги; иначе `ConflictError`. Повтор один раз. После успеха записанные теги становятся
    исходными, история очищается.
  - На боевом сервере перед отправкой — подтверждение.
  - Грабли: сайт OSM отдаёт COOP → `window.opener` в окне возврата пуст, `popup.closed` сразу true;
    code передаём через BroadcastChannel. Приложение OAuth должно быть не «конфиденциальным» (иначе
    `invalid_client`). `/changeset/{id}/upload` требует `Accept: application/xml|json` (иначе 406).
- 2026-10-07, этап 5 (скатные крыши на сложных контурах):
  - `straight-skeleton` (CGAL в Wasm, UMD, ~336 КБ gzip) — отдельный чанк через dynamic import; пока грузится,
    сложные крыши плоские, затем `BuildingsLayer.rebuildAll()`. В node нужны шимы `self` и `window`.
  - Грань скелета = скат над стороной контура (сторона — последняя и первая вершины грани), z = время × roofHeight / maxTime.
  - gabled: треугольные грани с двумя вершинами контура → фронтоны, вершина проецируется на сторону;
    короткие торцы первыми, общую вершину не двигаем дважды. Четырёхугольники — прежний код (учитывает roof:orientation).
- 2026-10-07, крыши round и ось почти прямоугольных контуров:
  - round — профиль дуги окружности; по скелету грани режутся на 8 полос по «времени» (clipT), фронтоны арочные.
  - На почти прямоугольных контурах (≥85% площади описанного прямоугольника, без дыр) gabled/round строятся
    вдоль оси прямоугольника с учётом roof:orientation (`addAxisRoof`): у почти квадратов скелет сходится в точку
    и даёт «купол» (relation/14483812). Скелет — для Г/Т-форм и контуров с дырами; hipped на четырёхугольниках — прежний код.
- 2026-10-07, крыши gambrel, mansard, half-hipped:
  - Профили (`PROFILES`): z(t) + точки излома; gambrel (0.3, 0.7) — с фронтонами, mansard (0.25, 0.75) — по скелету без фронтонов.
  - half-hipped: минимум четырёх плоскостей (`addPlanesRoof`), фронтон срезан на 60% высоты крыши вальмой того же уклона.
    Только на почти прямоугольных контурах; на сложных — как gabled.
- 2026-10-07, производительность просмотра:
  - Здания группы слиты в одну геометрию (цвет в вершинах, один материал) — один draw call на тайл вместо двух на здание.
    Выбор — по габаритам зданий, затем треугольники; подсветка — перекраска диапазона вершин.
  - Здание на границе тайлов рисуется только в тайле своего центра; части для контуров ищутся и в соседних тайлах
    (сетка ~50 м в `markOutlinesWithParts`, иначе O(здания × части) по девяти тайлам вешал страницу).
  - Разбор векторных тайлов кешируется на объекте тайла (WeakMap); setData/setFilter — только при изменениях.
  - Ниже z15 (до z10) — тайлы Overpass только из кеша, без сети.
  - Straight skeleton — в Web Worker со сторожем 2 с: на отдельных вырожденных контурах CGAL считал секундами.
  - `src/perf.ts`: `[perf]` в консоли (операции > 30 мс, long tasks), `perfReport()`; в dev включено всегда.
  - Готовые скелеты применяются пачкой (очередь пуста или раз в секунду), тайл пересобирается, только если появились крыши.
    Рёбра (EdgesGeometry, ~150 мс на плотный тайл) считаются по зданиям при порционной сборке и кешируются на них.
  - location=underground без тегов Simple 3D не рисуется (`shouldRender`).
